# PDF 견적서 품목 자동 인식 — 설계안

- 날짜: 2026-07-28
- 상태: 구현 완료

## 구현 후 발견되어 추가된 규칙 (2026-08-03)

실제 앱을 띄워 8개 샘플 전체를 다시 돌려본 결과, 아래 두 문제가 추가로 발견되어 수정되었다 (이 설계안 본문의 "표 추출" / "컬럼 매핑" 단계에 다음 두 규칙이 추가된 것으로 이해하면 된다):

- **헤더 탐색 범위**: `find_header_row`가 처음 5행만 훑도록 되어 있었는데, `세화볼트` 견적서는 사업자번호/주소 등 회사정보가 5줄 먼저 나오고 실제 헤더가 6번째 줄에 있어 헤더를 못 찾고 표 전체가 인식 실패로 처리됐다. 표 전체를 훑도록 수정했다 (실제 품목 데이터가 헤더 동의어와 우연히 정확히 일치할 위험은 무시할 수준으로 낮다고 판단).
- **헤더-첫행 융합 복구**: 원본 `견적서.pdf`는 헤더 행과 첫 품목 행 사이에 시각적 구분이 없어 `pdfplumber`가 둘을 같은 셀에 줄바꿈으로 합쳐서 추출했다 (예: `"품 명\nDESCRIPTION\n온습도검출기 온실용"`). 헤더 셀에서 인식된 라벨 다음에 남는 텍스트를 찾아 첫 품목 행으로 복원하는 로직을 추가했고, 이를 위해 "DESCRIPTION"을 품명(name) 동의어에 추가했다 (이 동의어가 있어야 일반적인 한/영 이중 라벨 헤더에서 잘못된 가짜 행이 만들어지지 않는다).

## 배경

지출결의서 작성 시 거래처 견적서(PDF)를 보고 품목/규격/단위/수량/단가를 수동으로 옮겨 적어야 한다. 실제 거래처 견적서 8개 샘플(`D:\claude_personal\setting_01\PDF_read`)을 `pdfplumber`/`PyMuPDF`로 분석한 결과, 전부 텍스트 기반 PDF(OCR 불필요)였고 표 추출 자체는 대부분 잘 되지만 아래 문제가 있었다:

1. 거래처마다 헤더 이름/순서가 다름 (품명 vs ITEM vs 공사명, 규격 vs 형식/색상, 수량↔단위 순서가 뒤바뀐 곳도 있음).
2. 대분류-세부품목이 섞인 계층형 표 (`온실제어장치` 견적서: "1. 온실제어 INTERFACE" 아래 수량/단가 없는 대분류 행 + 세부 품목 행).
3. 헤더가 중복 표기되어 어떤 컬럼이 단가/금액인지 모호함 (`한열사` 견적서: "단가"가 헤더에 2번 등장, 실제 값은 단가/금액 순서).
4. 표 자체가 없는 문단형 견적서 (`코랄` 견적서: "품 명 : AL-Ingot", "단 가 : 6,250,000원/MT" 식 텍스트만 존재).

완전 자동 100% 인식은 불가능하다고 판단, "최선을 다해 초안을 채우고 사용자가 검토/수정 후 확정"하는 방식으로 간다.

## 범위

- 이번 작업은 **품목 표(품명/규격/단위/수량/단가)만** 채운다. 업체명/날짜/제목 등 상단 정보는 다루지 않는다.
- 대상 PDF는 텍스트 기반 PDF로 한정한다 (스캔 이미지 PDF/OCR은 범위 밖).
- 샘플이 전부 1페이지였으므로 1차 구현은 페이지 단위로 반복 처리하되, 미리보기 이미지는 모든 페이지를 위→아래로 쌓아서 보여준다.

## 아키텍처

### 새 모듈: `pdf_item_parser.py`

```
parse_pdf_items(pdf_bytes: bytes) -> {
    "items": [{"name": str, "spec": str, "unit": str, "qty": float|None, "price": float|None}, ...],
    "page_images": [<page 1 PNG as base64>, <page 2 PNG as base64>, ...],
    "warnings": [str, ...],
}
```

내부 처리 순서 (순서대로 시도, 실패 시 다음 단계로):

1. **페이지 이미지 렌더링** — PyMuPDF(`fitz`)로 각 페이지를 PNG로 렌더링해 `page_images`에 채움 (미리보기용, 파싱 결과와 무관하게 항상 수행).
2. **표 추출** — `pdfplumber`로 모든 페이지의 표를 추출.
3. **품목 표 선별** — 추출된 표마다 헤더 행(또는 첫 데이터 행 근처)의 텍스트를 아래 "헤더 동의어 사전"과 비교해 매칭 점수를 매김. 품목명(name) 컬럼 매칭 + qty/price 중 최소 1개 매칭이 되는 표만 "품목 표" 후보로 인정. 여러 개면 매칭 점수가 가장 높은 표를 채택 (예: 회사 정보 key-value 표는 후보에서 자동 제외됨).
4. **컬럼 매핑** — 채택된 표의 각 컬럼을 헤더 동의어 사전으로 canonical field(name/spec/unit/qty/price)에 매핑. 매핑되지 않는 컬럼(순번/No/구분/비고/REMARK 등)은 버림.
5. **모호한 중복 헤더 보정** — 동일한 canonical field(주로 price)에 두 컬럼이 매핑되면: 첫 컬럼 후보를 단가, 둘째 컬럼 후보를 금액으로 가정하고, 행별로 `qty * price ≈ 금액` 관계가 성립하는지 검증. 성립하면 그 매핑 확정, 애매하면(qty 없음 등) 첫 컬럼을 단가로 쓰고 해당 행에 경고 플래그.
6. **계층형 대분류 처리** — 한 행의 name 컬럼에 값이 있고 spec/unit/qty/price가 전부 비어 있으면 그 행을 "대분류 행"으로 간주하고 결과에는 포함하지 않는다. 이후 등장하는 행(다음 대분류 행 전까지)의 name을 `f"{대분류명} - {원래 품명}"`으로 치환.
7. **빈 행/합계 행 제거** — 품명이 비어 있는 행, "합계"/"소계"/"이하여백" 등으로 시작하는 행은 제외.
8. **표가 없거나 매핑 실패 시 문단 패턴 매칭** — 표 추출이 실패했거나 3번에서 품목 표를 찾지 못한 경우, 페이지 텍스트를 줄 단위로 스캔해 `라벨 : 값` 패턴을 찾는다. 라벨은 공백이 섞여도 매칭되도록 정규화(예: "품 명" → "품명")해서 동의어 사전과 비교. 이렇게 찾은 값들로 최대 1개 품목 행을 구성.
9. **완전 실패** — 8번에서도 아무 것도 못 찾으면 `items=[]` + `warnings=["표를 인식하지 못했습니다. 직접 입력해주세요."]` 반환.

### 헤더 동의어 사전

| canonical | 동의어 |
|---|---|
| name | 품명, 품 명, 공사명/품명, ITEM, 물품명 |
| spec | 규격, 규 격, SIZE, 형식, 규격/색상, 사양 |
| unit | 단위, 단 위, UNIT |
| qty | 수량, 수 량, Q'TY, QTY |
| price | 단가, 단 가, UNIT PRICE |

버림: 순번, No, 구분, 비고, REMARK, 납기 등 위 목록에 없는 헤더.

### Flask 라우트

`POST /parse_pdf` (multipart file upload, `app.py`에 추가) — `pdf_item_parser.parse_pdf_items()`를 호출하고 JSON으로 결과 반환.

### 프론트엔드 (`templates/index.html`)

- 품목 표 위에 "PDF로 품목 불러오기" 버튼 + 숨겨진 파일 입력 추가.
- 파일 선택 시 `/parse_pdf`로 업로드 → 같은 페이지 위 팝업(모달) 오픈.
- 모달 구성: 좌측에 `page_images`를 위→아래로 쌓아서 표시, 우측에 파싱된 `items`를 채운 수정 가능한 표(행 추가/삭제 가능), `warnings`는 모달 상단에 안내 문구로 표시.
- 모달 하단 버튼: "취소" / "표에 적용".
- "표에 적용" 클릭 시 선택창 노출:
  1. **기존 내용 삭제 후 업로드한 내용으로 작성** — 기존 품목 행을 전부 지우고 모달의 표 내용으로 교체.
  2. **기존 내용 유지 후 업로드한 내용 추가** — 기존 품목 행 뒤에 모달의 표 내용을 추가.
- 선택 후 모달 닫고 메인 품목 표에 반영.
